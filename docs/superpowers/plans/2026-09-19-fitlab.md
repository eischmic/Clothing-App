# FitLab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a runnable Expo app where a user uploads inspiration images and their wardrobe, receives an AI-generated style profile that reskins the app to their palette, and gets explained product recommendations that expand the outfits they can assemble.

**Architecture:** Expo Router file-based navigation with a first-run onboarding funnel gating five tabs. All recommendation intelligence lives in pure, unit-tested modules under `lib/` with no React imports; screens are thin consumers of a Zustand store. Vision calls run in Expo Router API routes so the Anthropic key never enters the client bundle.

**Tech Stack:** Expo SDK 54+, Expo Router, TypeScript (strict), Zustand + AsyncStorage, react-native-reanimated, react-native-svg, expo-image-picker, expo-linear-gradient, `@anthropic-ai/sdk`, Jest (`jest-expo` preset).

**Spec:** `docs/superpowers/specs/2026-09-19-fitlab-design.md`. Read it before starting. Where this plan and the spec disagree, the spec wins.

## Global Constraints

- Package manager: `npm`. Never introduce a second lockfile.
- TypeScript `strict: true`. No `any` in `lib/`. No `@ts-ignore` without an adjacent one-line reason.
- Path alias `@/*` → repo root. Configured in `tsconfig.json`.
- `lib/**` must never import React, React Native, or Expo. It is pure TypeScript. This is what makes it testable and is enforced by Task 6's lint test.
- The dark base palette is fixed. Only the accent ramp varies. Exact base values: canvas `#0A0A0B`, elev1 `#101012`, elev2 `#17171A`, elev3 `#1F1F23`, hairline `#2A2A2F`, textHi `#F5F4F2`, textMid `#A3A09C`, textLow `#6B6862`.
- The six vibe accents, verbatim: Noir `#E8E6E3`, Ember `#FF7A45`, Sage `#7FB77E`, Cobalt `#4D7CFE`, Orchid `#B57EDC`, Sand `#D9B382`.
- Score weights, verbatim: `style 0.50`, `wardrobe 0.20`, `price 0.15`, `occasion 0.15`.
- Vector blend weights, verbatim: `IMAGE_WEIGHT = 0.6`, `QUESTIONNAIRE_WEIGHT = 0.4`.
- The nine style dimensions, in this canonical order: `minimalism`, `streetwear`, `workwear`, `outdoor`, `vintage`, `formal`, `colorfulness`, `pattern`, `relaxedFit`.
- Theme transition: 320 ms, `Easing.bezier(0.22, 1, 0.36, 1)`.
- Model id for all Claude calls: `claude-sonnet-4-6`.
- `ANTHROPIC_API_KEY` must never appear with an `EXPO_PUBLIC_` prefix, and never outside `app/api/`.
- Cut list is binding: no auth, payments, checkout, feed, followers/following, scraping, try-on.
- Every task ends with a commit. Conventional-commit prefixes (`feat:`, `test:`, `chore:`, `fix:`).
- The app must remain runnable via `npx expo start` → `w` at the end of every task from Task 5 onward.

- [ ] **Step 4: Implement `theme/ThemeProvider.tsx` and `theme/useTheme.ts`**

`ThemeProvider` holds `mode: 'auto' | VibeName` and the resolved vibe. When the resolved vibe changes, drive `accentProgress` from 0 to 1 with `withTiming(1, { duration: DURATION.theme, easing: Easing.bezier(...EASING_BEZIER) })`, keeping the previous ramp in state so consumers can interpolate between `prevRamp` and `ramp`. Expose:

```ts
export interface ThemeValue {
  base: typeof BASE;
  accent: VibeRamp;
  prevAccent: VibeRamp;
  vibe: VibeName;
  mode: 'auto' | VibeName;
  setMode: (m: 'auto' | VibeName) => void;
  accentProgress: SharedValue<number>;
  spacing: typeof SPACING;
  radii: typeof RADII;
  type: typeof TYPE;
}
```

`useTheme()` throws a clear error if called outside the provider — that is a programming mistake, not a runtime condition, so it should fail loudly.

The provider accepts `profileVibe: VibeName | null` as a prop rather than reading the store, so it stays independent of Zustand and is trivially testable. In `auto` mode the resolved vibe is `profileVibe ?? 'noir'`.
